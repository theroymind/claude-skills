# Reorganize

Restructure files into clear groupings while keeping git history and every reference working.

## Steps

1. **Survey.** Detect the language from the build files, map the current tree (noting conventions that are followed inconsistently), and sample how imports work (relative, absolute, path aliases). Note paths a framework requires (Rails expects `app/models/`), generated files ("DO NOT EDIT", "generated by") and symlinks.
2. **Ask** about whatever the user hasn't already said, in one `AskUserQuestion` call with your recommendation first in each question:
   - **Scope**: the whole project or one directory. For a large monorepo, recommend one package at a time.
   - **Strategy**: module-based (by feature or domain, for larger projects with distinct domains), type-based (`components/`, `services/`, for smaller projects that share a lot of code), or hybrid (`components/auth/`).
   - **Tests**: next to their source (`foo.lua` beside `foo_test.lua`) or in a separate `tests/` tree.
   - **Barrel files** (`index.ts`, `__init__.py`, `init.lua`, `mod.rs`): for or against, recommended for the language.
3. **Propose** the new layout as a tree. Explain where any file could reasonably live in two places. List the files that don't fit cleanly, the generated files and the framework-required paths, and ask where each should go. Get approval with `AskUserQuestion`; for changes, revise the tree and ask again.
4. **Move** the files with `git mv`, in batches grouped by source directory: create the new directories, move the files, then remove the empty directories left behind. Outside git, use plain moves and tell the user that history won't be kept.
5. **Update the references.** Dispatch Haiku agents (`model: "haiku"`) in parallel, one per moved file or small group of related files. Each one searches for every form of the old path, edits each match, and reports what it changed. Forms to cover: with and without the extension, relative and absolute, path aliases, Lua dotted `require`, Python dotted imports, Go module paths, Rust `use crate::`. Non-code references need updating too: tsconfig paths and bundler aliases, `.luarc.json`, Makefiles, CI workflows, Dockerfiles, the `main`, `exports` and `files` fields in `package.json`, and docs.
6. **Verify.** Run the test suite and the linter, then search for any remaining references to old paths. Fix failures before reporting. If the move exposes circular imports, flag them to the user instead of working around them.
